# CreativeOS PRD v2.0 开发升级规划

## 一、现状与差距（已勘察确认）

v1.0 主轴已落地：`packages/core`（零依赖领域库）→ `dsh-adapter`（唯一 cordis 接触面）→ 8 个 `opc-*` 插件 → `opcos-bundle`（单层 insert patch）→ `opcos-console`（11 面板，原生 JS 单文件前端）。测试 `node --test`、SQLite 用 `node:sqlite`、创意变现漏斗（创意→作品→技能→收入）已跑通。

对照 PRD v2.0 的缺口：

| PRD v2.0 概念 | 现状 |
|---|---|
| 创意一等公民（实体/阶段/三域） | 仅 topic 记忆条目（`opcos-console/src/api.ts:1130`） |
| 独立记忆体 + FTS5 + /mount 挂载 | 全局双记忆，LIKE 检索（`core/memory/sqlite-store.ts:131` 留有 FTS5 升位点） |
| 子操作系统 Profile + 阶段切换 | 无 |
| 多平台分发 / 每创意人设隔离 | 仅公众号 Mock 适配器（`core/content/types.ts`）；人设记忆为共享单实例 |
| GEO 行销 / 监测插件 | 无 |
| 五类资产账本 + Meme Token | 仅 split_ledger 分成流水；无 Token、无每创意账本 |
| 创意市场（IM-01~06） | 无 |
| 技能市场 v2（.skillpkg/阶段分类/订阅定价） | 有 .dshpkg 市场 + 订单分成 85/15，缺 v2 增量 |

## 二、总体策略与关键决策

- **沿用仓库既有约定**：core 零 DSH 依赖；插件薄适配、服务名 `opc.*`、运行时 `getService` 解析；测试与源码同置 `*.test.ts`；SQLite 用 `node:sqlite`；前端继续原生 JS 单文件（不引入框架）。
- **插件命名沿用 `opc-*`**（dev-design 约定），PRD 中 `creativeos/*` 作为逻辑名映射到物理插件，在代码注释与文档中标注对应关系。
- **Meme Token 按积分账本实现**（PRD R-02 自己的缓解措施：不上链、仅社区积分、不承诺金融回报），数据形态对齐 PRD 6.5（token/config.json + distribution.json），分配模型 45/25/20/10。
- **外部依赖全部走"Mock + DeepSeek 真实策略可插拔降级"**（沿用 MockWechatAdapter / DEEPSEEK_API_KEY 既有模式）：多平台分发为平台适配器接口 + 各平台 Mock；GEO 监测为 Provider 接口 + MockProvider + DeepSeek 估值 Provider。
- **`.skillpkg` 与 `.dshpkg` 共存**：新格式在既有 Ed25519 信封上加 stage/category/compatible_ideas/memory_snapshot 字段，旧包继续可安装。
- 每个里程碑独立可交付、`npm test` 全绿后提交（conventional commits，中文描述）。

## 三、里程碑规划

### M1 创意一等公民内核（ID-01/02/03 + 记忆系统 P0）
- 新增 `packages/core/src/idea/`：
  - `types.ts`：Idea 实体（id/name/stage/threeDomains/createdAt…）、`IdeaStage`（description|product|operation|asset）、三域结构 + 每域 ≥3 个引导问题（ID-02）。
  - `store.ts`：SqliteIdeaStore（ideas 表，三域 JSON 列）+ 目录脚手架 `$DSH_HOME/ideas/<id>/`（memory-body 四个 JSONL、assets/ledger.json、token.json、profile/cordis.patch.yml、meta.json，ID-03 成功率 100% 验收）。
  - `three-domains.ts`：自然语言 → 三域草案（规则抽取策略 + 可选 LLM 策略，ID-01）。
- 记忆体升级 `packages/core/src/memory/`：
  - SQLite 存储加 FTS5 虚表 + 触发器，keyword 查询走 FTS5（不可用时自动回退 LIKE，中英文 ≥3 字子串命中）。
  - `MemoryBody` 抽象：每创意独立 JSONL + 独立索引；`MountManager`：会话级挂载集合，`mount/unmount`，检索只命中已挂载记忆体（PRD 8.3 四行隔离表逐项有测试）。
- 控制台 API 改造：`POST /api/ideas` 升级为创建 Idea 实体（保留 topic 记忆镜像以兼容内容流水线）；新增 `GET /api/ideas/:id`、三域编辑、`POST /api/mount`。
- 测试：三域草案、记忆体创建、跨创意检索零命中、FTS5 检索、挂载切换。

### M2 子操作系统与生命周期编排（子OS P0 + IP-01/02/03）
- 新增 `packages/dsh-plugins/opc-lifecycle/`（对应 PRD lifecycle-manager）：
  - 阶段状态机 + 迁移配置（PRD 3.4 的 stage_transition：add_plugins、memory_write 写 decisions.jsonl）。
  - 创建/切换阶段时生成 `ideas/<id>/profile/cordis.patch.yml`（PRD 2.5 结构，按阶段装配插件组合）。
- 新增 `packages/core/src/mvp/`：MvpPlanner（IP-01：三域 → 功能清单/技术栈/开发计划，模板 + 可选 LLM 策略）；工作区隔离 `ideas/<id>/workspace/`（IP-02）；验证记录写记忆体（IP-03）；Go/No-Go 建议（IP-04）。
- 控制台：创意详情面板（阶段进度条、三域编辑器、挂载开关、MVP 方案视图）。
- 测试：阶段迁移合法性、Profile 生成、工作区越界拒绝、迁移记忆写入。

### M3 内容运营升级（CO-01/02/03 + GEO）
- `packages/core/src/content/` 扩展：
  - 平台适配器注册表：在 MockWechatAdapter 基础上增小红书/抖音/Twitter/B站 Mock 适配器（CO-03，适配 <30s/平台）。
  - 人设隔离（CO-02）：人设记忆改由创意记忆体供给，流水线按 ideaId 取人设；personaScore ≥4/5 验收保留。
- GEO 能力（PRD 4.3 四策略）：每创意 `facts.jsonl` 品牌事实库；审核阶段加 E-E-A-T 四维检查；分发阶段生成 Schema JSON-LD；选题策略对 FAQ/指南/对比类结构化选题加权。
- 新增 `packages/dsh-plugins/opc-geo-monitor/`：指标存储（visibility/citation_rate/sentiment × 平台）、Mock + DeepSeek 估值双 Provider、visibility_drop 0.2 告警、监测数据写入创意记忆体、刷新 <5min。
- 控制台：内容引擎面板升级（平台矩阵、创意选择器）+ 新增 GEO 面板。
- 测试：多平台适配、人设隔离互不干扰、E-E-A-T 检出、Schema 生成、告警触发。

### M4 产品资产：五类账本 + Token 积分 + Skill 归属
- 新增 `packages/core/src/asset/`：IdeaLedger 按 PRD 5.5 JSON 结构（skills/tokens/finance/users/analytics），事件挂钩：订单分成 → finance、内容发布/GEO 指标 → analytics。
- 新增 `packages/core/src/token/` + `opc-token-manager` 插件：积分账本（config/distribution），按 45/25/20/10 模型与事件发放（MVP 反馈、内容贡献、协同）。
- Skill 归属创意：PatternMiner/Distiller 草案携带 ideaId；packager 产出 `.skillpkg`（stage/category/compatible_ideas/memory_snapshot，PRD 7.5），保持 .dshpkg 兼容。
- 控制台：创意资产面板升级为五类资产 + Token 分布视图。
- 测试：账本事件同步、Token 分配守恒、.skillpkg 签名与兼容安装。

### M5 创意市场 + 技能市场 v2（IM-01~05 + SM-01~04）
- 新增 `packages/core/src/idea-market/` + `opc-idea-market` 插件：
  - summary.json 公开摘要发布（ID-05，本地市场即时可检索）；关联发现（互补/相似：三域文本相似度 + 关键词 + 阶段互补评分，纯 TS 实现不引外部向量库）；关注 + 阶段变更通知；FTS5 搜索 <500ms；排行榜（by_assets/by_community/by_geo）。
  - 协同机制：collaborators.json + 贡献记录 + 按 PRD 6.4 权重表分配 Token。
- 技能市场 v2：阶段/类别筛选（SM-01）；安装到指定创意子 OS（SM-02）；三步发布流（SM-03）；定价模型扩展 免费/一次性/订阅（SM-04，orders 引擎加订阅类型）。
- 控制台：新增创意市场面板（浏览/关注/关联/排行）+ 技能市场面板升级。
- 测试：关联推荐、关注通知、搜索性能、协同 Token 分配、订阅订单。

### M6 收口：非功能需求 + 联调 + 文档
- NFR 落地与验证（PRD 10）：挂载切换 <500ms、市场搜索 <500ms（bench 测试，沿用 storage-bench 模式）、记忆体隔离零交叉、1000 创意规模基准。
- 全链路：opcos-bundle `demo.ts` 增加"创意录入→三域→MVP→运营→资产→市场"步骤；funnel API 切换到 Idea 实体口径；cordis.patch.yml 增补新插件行。
- 文档：dev-design.md 追加 v2 架构章节（新模块/插件/数据契约）、readme 更新、PRD 需求编号 ↔ 测试文件映射表。

## 四、验证方式

- 每里程碑：`npm test`（tsc + node --test）全绿；新增测试覆盖上述各条验收点。
- `npm run console` 手工冒烟：创意录入 → 详情三域编辑 → 阶段切换 → 内容/GEO → 资产/市场页面可用。
- `npm run demo` 全链路演示通过后提交。

## 五、说明与风险

- PRD 9.1 的统计数字（P0×18 vs 模块表加总 24）文档内部不一致，按模块表 P0 逐条覆盖执行，执行中以需求编号为锚。
- Meme Token 为积分账本而非链上实现（R-02 合规缓解），接口形态预留 chain provider 扩展位。
- GEO 监测的平台可见性无公开 API，Mock/估值数据在 UI 明确标注为模拟口径，避免误读为真实投放数据。
- 全量交付量大（6 个里程碑），按序提交，M1+M2 完成即形成"创意一等公民"最小闭环，后续每个里程碑都是独立可停的增量。
