## 1. 产品概述

### 1.1 产品定位

CreativeOS 是一套以"创意"为基本单元的变现操作系统，运行在DSH之上，通过插件化方式为每个创意提供全生命周期管理、独立记忆系统、子操作系统，并通过创意市场与技能市场实现创意的互联与变现。

与v1.0的核心差异：v1.0的单元是"Agent"和"工具"；v2.0的单元是 **"创意（Idea）"**。每个创意是一个独立的生命体，拥有自己的记忆、自己的子操作系统、自己的资产账本。

### 1.2 创意生命周期模型

### 1.3 产品单元：创意（Idea）

每个创意是一等公民，拥有：

| 属性 | 说明 |
|---|---|
| 创意ID | 全局唯一标识 |
| 创意名称 | 用户可命名 |
| 当前阶段 | 描述/产品/运营/资产 |
| 独立记忆体 | 存储该创意所有上下文、决策、数据 |
| 子操作系统 | 管理该创意全生命周期的Profile |
| 资产账本 | 记录该创意产生的所有资产 |
| 协作关系 | 与其他创意的关注/关联/协同关系 |
| Meme Token | 该创意的社区激励凭证 |

## 2. 阶段一：创意描述

### 2.1 功能概述

用户以自然语言描述一个创意，系统通过结构化引导将其拆解为问题域、解决域、时空域三个维度，并初始化该创意的独立记忆体和子操作系统。

### 2.2 三域框架

| 维度 | 定义 | 引导问题 | 输出 |
|---|---|---|---|
| 问题域 | 创意要解决什么问题 | 谁在什么场景下遇到什么问题？现有方案为何不够好？ | 问题陈述、目标用户、现有替代方案 |
| 解决域 | 用什么方案解决 | 你的方案是什么？核心差异化在哪？ | 解决方案概述、核心功能、差异化点 |
| 时空域 | 在什么时空条件下有效 | 这个创意在什么时间窗口、什么地域/文化/技术条件下成立？ | 时机分析、市场窗口、约束条件 |

三域并非线性流程，而是共演化关系：问题结构化的过程会推动知识扩展和方案生成，三者通过迭代映射相互影响。系统应支持用户在三域之间自由切换、反复迭代。

### 2.3 功能需求

| 编号 | 功能 | 优先级 | 描述 | 验收标准 |
|---|---|---|---|---|
| ID-01 | 创意录入 | P0 | 用户以自然语言描述创意，系统自动识别关键信息 | 录入后自动生成三域草案 |
| ID-02 | 三域引导 | P0 | 系统通过结构化问题引导用户完善问题域、解决域、时空域 | 每个维度至少3个引导问题 |
| ID-03 | 创意初始化 | P0 | 为每个创意创建独立记忆体和子操作系统 | 记忆体创建成功率100% |
| ID-04 | 创意版本 | P1 | 支持创意描述的版本迭代，保留历史 | 可回滚至任意历史版本 |
| ID-05 | 创意发布 | P1 | 将创意摘要发布至创意市场，供他人浏览和关注 | 发布后30秒内可在市场检索到 |

### 2.4 独立记忆系统初始化

每个创意在创建时自动初始化一个独立的**记忆体（Memory Body）**。基于LMA（Layered Memory Architecture）的记忆体抽象，每个创意对应一个命名记忆单元，物理上是一个目录 + JSONL文件。

创意记忆体的初始结构：

```
$DSH_HOME/ideas/<idea-id>/
├── memory-body/
│   ├── description.jsonl     # 创意描述、三域分析
│   ├── decisions.jsonl       # 关键决策记录
│   ├── research.jsonl        # 调研数据
│   └── model-notes.jsonl     # 模型自动总结的经验
├── assets/
│   ├── ledger.json           # 资产账本
│   └── token.json            # Meme Token配置
├── profile/
│   └── cordis.patch.yml      # 该创意的子操作系统配置
└── meta.json                 # 创意元数据（名称、阶段、协作关系）
```

**记忆体挂载机制**：通过`/mount <idea-id>`命令控制当前会话能检索哪些创意的记忆体。记忆体中的数据是持久的，但挂载是按会话动态控制的。这意味着：

- 处理创意A时，只挂载创意A的记忆体，创意B的记忆不会被检索到
- 需要跨创意协作时，可同时挂载多个记忆体
- 每个创意的记忆体拥有独立的FTS5全文检索索引

### 2.5 子操作系统初始化

每个创意在创建时自动生成一个子操作系统Profile，该Profile包含：

```yaml
# $DSH_HOME/ideas/<idea-id>/profile/cordis.patch.yml
idea_id: "<idea-id>"
idea_name: "<用户命名>"
stage: "description"
memory_body: "$DSH_HOME/ideas/<idea-id>/memory-body"
plugins:
  - id: idea-memory
    name: "@szx-a/dsh-layered-memory-architecture"
    config:
      defaultBodies: ["<idea-id>"]
  - id: stage-guide
    name: "creativeos/stage-guide"
    config:
      currentStage: "description"
      enableThreeDomains: true
  - id: idea-asset-ledger
    name: "creativeos/asset-ledger"
    config:
      ledgerPath: "$DSH_HOME/ideas/<idea-id>/assets/ledger.json"
```

子操作系统随创意生命周期阶段自动切换插件组合——阶段一加载三域引导插件，阶段二加载MVP开发插件，阶段三加载内容运营与GEO插件，阶段四加载资产管理与交易插件。

## 3. 阶段二：创意产品

### 3.1 功能概述

将创意描述转化为可运行的产品。分为两步：MVP开发（用DSH快速验证）和生产型产品（规模化交付）。

### 3.2 功能需求

| 编号 | 功能 | 优先级 | 描述 | 验收标准 |
|---|---|---|---|---|
| IP-01 | MVP引导 | P0 | 系统基于三域分析，自动推荐MVP功能范围和技术选型 | 生成的MVP方案包含功能清单、技术栈、开发计划 |
| IP-02 | DSH开发环境 | P0 | 在创意的子操作系统内启动DSH Agent执行开发任务 | Agent可读写创意工作区文件 |
| IP-03 | MVP验证 | P0 | 记录MVP的验证结果（用户反馈、数据指标） | 验证结果写入创意记忆体 |
| IP-04 | 产品化决策 | P1 | 基于MVP验证数据，辅助决策是否进入生产型产品开发 | 提供Go/No-Go建议 |
| IP-05 | 生产型产品开发 | P1 | 扩展MVP为可规模化交付的产品 | 产品可独立部署和交付 |
| IP-06 | 版本管理 | P1 | 产品版本的迭代记录与回滚 | 支持语义化版本 |

### 3.3 技术实现

MVP开发阶段使用DSH的标准Agent能力，但所有操作限定在创意的子操作系统Profile内。关键约束：

- **工作区隔离**：每个创意的工作区为`$DSH_HOME/ideas/<idea-id>/workspace/`，Agent不能访问其他创意的工作区
- **记忆注入**：开发过程中产生的技术决策、架构选择自动写入创意记忆体的`decisions.jsonl`
- **本能提炼**：`dsh-plugin-long-term-memory`的Instinct系统观测Agent的工具使用模式，为后续Skill沉淀积累数据

### 3.4 阶段切换

当MVP验证通过后，子操作系统自动从`description`阶段切换到`product`阶段，加载生产型产品开发所需的插件：

```yaml
# 阶段切换配置
stage_transition:
  from: "description"
  to: "product"
  add_plugins:
    - id: product-dev
      name: "creativeos/product-dev"
    - id: quality-gate
      name: "creativeos/quality-gate"
  memory_write:
    target: "decisions.jsonl"
    content: "MVP验证通过，进入生产型产品开发阶段"
```

## 4. 阶段三：产品运营

### 4.1 功能概述

产品上线后，通过内容运营和GEO行销获取用户和增长。

### 4.2 内容运营

| 编号 | 功能 | 优先级 | 描述 | 验收标准 |
|---|---|---|---|---|
| CO-01 | 内容流水线 | P0 | 选题→创作→审核→分发→反馈六阶段自动化 | 单篇内容全流程 < 30分钟 |
| CO-02 | 人设记忆 | P0 | 每个创意独立的品牌人设记忆 | 人设一致性评分 ≥ 4/5 |
| CO-03 | 多平台分发 | P0 | 公众号/小红书/抖音/Twitter/B站 | 适配时间 < 30s/平台 |
| CO-04 | 数据回收 | P1 | 内容表现数据自动回收至创意记忆体 | 回收延迟 < 1小时 |
| CO-05 | 内容资产化 | P1 | 表现优异的内容沉淀为可复用模板 | 模板可直接用于同类创意 |

**人设记忆的独立性**：每个创意的内容人设存储在各自的记忆体中。创意A的"硬核科技评论员"人设与创意B的"温柔生活方式博主"人设完全隔离，互不干扰。

### 4.3 GEO行销

GEO（Generative Engine Optimization，生成式引擎优化）是AI搜索时代的核心营销能力。品牌方需要针对豆包、DeepSeek等主流生成式AI大模型的语义识别逻辑和答案生成偏好，对品牌信息、商品内容、口碑资产进行系统性优化。

核心策略：

| 策略 | 说明 | 技术实现 |
|---|---|---|
| E-E-A-T强化 | 经验、专业、权威、可信度四维内容建设 | 内容审核Agent自动检查E-E-A-T要素 |
| 结构化知识内容 | FAQ、选购指南、比较分析等可直接回答问题的内容 | 选题Agent优先推荐结构化内容选题 |
| Schema标记 | 结构化数据标记提升被引用概率 | 分发Agent自动生成Schema标记 |
| 品牌事实库 | 建立可被AI引用的品牌事实库 | 创意记忆体中的facts.jsonl作为事实源 |

效果指标参考：某美妆品牌通过GEO优化后，在豆包的可见性从15%提升至89%；某金融科技品牌AI问答提及率从0%提升，首推率达42%。

### 4.4 GEO监测插件

新增GEO监测插件，7×24小时监测主流AI平台上该创意的品牌表现：

```yaml
- id: geo-monitor
  name: "creativeos/geo-monitor"
  config:
    idea_id: "<idea-id>"
    platforms: ["doubao", "deepseek", "chatgpt", "wenxin"]
    brandKeywords: ["<创意名称>", "<产品名称>"]
    metrics: ["visibility", "citation_rate", "sentiment"]
    alertThreshold:
      visibility_drop: 0.2  # 可见性下降20%触发告警
    writeToMemory: true  # 监测数据写入创意记忆体
```

### 4.5 阶段切换

产品运营稳定后（如月活用户连续3个月增长），子操作系统切换到`asset`阶段，加载资产管理插件。

## 5. 阶段四：产品资产

### 5.1 功能概述

创意在运营过程中积累的五类资产：Skill沉淀、Meme Token、财务收入、用户资源、运营数据。

### 5.2 五类资产

| 资产类型 | 定义 | 存储位置 | 变现方式 |
|---|---|---|---|
| Skill沉淀 | 该创意中提炼出的可复用工作流 | 创意记忆体 + 技能市场 | 上架技能市场交易 |
| Meme Token | 该创意的社区激励凭证 | 链上/创意资产账本 | 社区众筹、激励分配 |
| 财务收入 | 产品收入、订阅收入、分成收入 | 资产账本ledger.json | 直接提现/再投资 |
| 用户资源 | 用户列表、社群、粉丝画像 | 创意记忆体users.jsonl | 精准营销、产品推荐 |
| 运营数据 | GEO数据、内容表现、转化漏斗 | 创意记忆体analytics.jsonl | 数据驱动的决策优化 |

### 5.3 Skill沉淀

从创意生命周期的全过程中自动提炼可复用Skill：

- 阶段一：三域分析的方法论可沉淀为"创意拆解Skill"
- 阶段二：MVP开发中的技术方案可沉淀为"XX类产品开发Skill"
- 阶段三：GEO优化策略可沉淀为"GEO内容优化Skill"
- 阶段四：资产管理流程可沉淀为"创意资产评估Skill"

提炼机制基于`dsh-plugin-long-term-memory`的Instinct系统，观测工具调用序列，当重复≥3次且质量达标时触发蒸馏。

### 5.4 Meme Token设计

每个创意可发行自己的Meme Token，用于社区激励和协同参与。

Token生命周期与创意生命周期对应：

| Meme Token阶段 | 对应创意阶段 | 社区行为 |
|---|---|---|
| 部署 | 创意描述 | 创建Token，设定初始供应量 |
| 社会资本形成 | 创意产品 | 社区成员参与MVP测试获取Token |
| 去中心化交易 | 产品运营 | Token可在市场交易 |
| 价值创造与分配 | 产品资产 | 收入分配、社区治理 |

参考Pump.fun的模式，任何人可以在几分钟内创建基于Solana的代币。Meme Token的核心价值在于将社区注意力转化为可量化的链上参与。

Token分配模型（建议）：

| 用途 | 比例 | 说明 |
|---|---|---|
| 社区激励 | 45% | 内容创作、测试反馈、推广传播 |
| 创作者 | 25% | 创意发起人 |
| 协同贡献 | 20% | 参与创意不同阶段的协作者 |
| 生态储备 | 10% | 平台运营和流动性 |

## 6. 创意市场

### 6.1 功能概述

创意市场是一个全网创意的展示、发现与协作平台。用户可以浏览所有公开创意，关注感兴趣的创意，建立关联，并参与协同。

### 6.2 功能需求

| 编号 | 功能 | 优先级 | 描述 | 验收标准 |
|---|---|---|---|---|
| IM-01 | 创意展示 | P0 | 展示全网创意的摘要、阶段、资产概况 | 支持按阶段/热度/类别筛选 |
| IM-02 | 关注 | P0 | 关注感兴趣的创意，接收更新通知 | 关注后收到阶段变更通知 |
| IM-03 | 关联发现 | P0 | 自动发现互补/相似的创意 | 关联推荐准确率 ≥ 70% |
| IM-04 | 协同参与 | P0 | 参与创意不同生命阶段的工作，获取Meme Token | 协同记录上链/写入账本 |
| IM-05 | 创意搜索 | P1 | 按关键词、三域、阶段搜索创意 | 搜索响应 < 500ms |
| IM-06 | 创意排行榜 | P1 | 按资产规模、社区活跃度、GEO表现排名 | 每日更新 |

### 6.3 关联发现机制

系统自动分析创意的三域特征，发现两类关联：

**互补关联**：两个创意在问题域或解决域上互补。例如：

- 创意A（问题域：跨境电商选品难）与创意B（解决域：AI选品工具）→ 互补
- 创意A（解决域：AI客服）与创意B（解决域：订单管理）→ 产品互补

**相似关联**：两个创意在问题域或解决域上高度相似。例如：

- 创意A（问题域：独立开发者获客难）与创意B（问题域：小团队获客难）→ 相似
- 可触发合并建议或协同建议

关联算法基于三域文本的向量相似度 + 关键词匹配 + 阶段互补性评分。

### 6.4 协同机制

**跨阶段协同**：不同用户可以在创意的不同生命阶段参与贡献。例如：

- 用户X擅长创意描述 → 参与阶段一，贡献三域分析
- 用户Y擅长开发 → 参与阶段二，贡献MVP代码
- 用户Z擅长内容运营 → 参与阶段三，贡献GEO策略
- 用户W擅长资产管理 → 参与阶段四，贡献Skill提炼

每次协同贡献记录在创意资产账本的`collaborators`字段，并按贡献度分配Meme Token。

协同收益分配：

| 协同角色 | 贡献类型 | Token分配权重 |
|---|---|---|
| 创意发起人 | 三域定义、方向决策 | 25% |

| 内容运营者 | 内容创作、GEO优化 | 20% |
| 资产管理者 | Skill提炼、财务管理 | 10% |
| 社区推广者 | 传播、拉新 | 15% |
| 平台 | 基础设施、匹配 | 10% |

### 7.4 技能交易基础设施

参考腾讯SkillPay的支付体系设计。SkillPay首次将技能分发、Agent调用与技能支付在同一条链路上打通。技能市场应提供：

- **微信支付AI专属卡**：以AI专属卡作为付费入口，用户授权后即可用卡内余额安全完成Pay Skill的调用与支付
- **升级为Pay Skill**：专业能力通过简易改造即可升级为Pay Skill，被Agent调用并创造营收
- **任务中完成支付**：Agent调用Pay Skill时在任务流程中原生触发支付，付费与交付不中断、不跳转
- **可信调用保障**：保障Pay Skill被调用时来源可靠、内容完整与安全

分成比例：创作者85%，平台15%。

### 8.3 记忆体挂载与隔离机制

每个创意对应一个独立的**记忆体（Memory Body）**。基于LMA的实现，记忆体具有以下特性：

- **命名**：每个记忆体有唯一名称（即创意ID）
- **跨会话**：数据持久存储，不随会话结束而丢失
- **隔离**：不同创意的记忆体物理隔离，数据不交叉
- **可挂载**：通过`/mount <idea-id>`控制当前会话能检索哪些记忆体
- **双权威**：`user`（用户钦定的文档）vs `model`（模型自动总结的经验）
- **FTS5全文检索**：中英文3字以上任意子串命中

挂载协议：

```
# 处理单个创意
/mount idea-001

# 跨创意协作（同时挂载多个）
/mount idea-001 idea-002 idea-003

# 卸载
/unmount idea-001
```

隔离保障：

| 隔离维度 | 机制 | 验证方式 |
|---|---|---|
| 数据隔离 | 每个创意独立目录 + JSONL文件 | 文件系统权限检查 |
| 检索隔离 | 独立FTS5索引，挂载按会话控制 | 跨创意检索测试 |
| 记忆注入隔离 | 只有已挂载的记忆体才注入系统提示 | Prompt审查 |
| Agent Scope隔离 | 每个live agent拥有扁平注册层agent.ctx | 官方隔离规则验证 |
